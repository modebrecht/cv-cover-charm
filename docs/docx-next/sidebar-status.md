**Historical one-row checkpoint:**

Brief is the neutral reference for the first shared native Sidebar candidate. `modern` is also a **CV layout choice**, independent of the registered **Modern template**. Modern's earlier candidate evidence covers a classic CV. No template is newly Word accepted here: **29/39 configured candidates, 0/39 Word accepted. Microsoft Word acceptance: pending.**

The new `parallel-flow` primitive uses one splittable native Word row with independently flowing cells and a gutter. Cell fill, padding and divider borders are native. CV mapping partitions sections by saved placement, merges the app's default placements, mirrors physical track order, and retains semantic IDs and authored run styles. `cv-sidebar-composition.ts` owns this mapping; `native-cell.ts` owns cell properties. One renderer handles every template. There is no template-ID renderer branch, visible-text styling, measured PDF pagination, legacy reconstruction or post-export XML repair.

Native entry groups use optional `keepTogether` rows: short entries stay together; descriptions larger than a page remain native and flow across pages. Layout widths use the **usable Word content grid minus the 6 mm gutter**, with the saved 22–42% side fraction. This differs from the browser's sheet-relative rail. The side cell has 3 mm padding, an 8% accent tint and a 0.25 mm inner divider. Personal information stacks in the narrow rail. These are explicit Word flow adaptations, not approved browser parity.

The candidate is intentionally restricted. Active running header stories, including compact empty surface carriers and separate first-header stories, fail before export. Different first/continuation top margins, free CV photos, explicit page-two starts inside either track, nested column flow and floating semantic content in a track also fail explicitly. Auto/left/right photo fixtures retain native pictures, authored width, crop, frame and physical placement; oversize pictures fail. The editor converts old photo modes into free geometry, so live-editor Sidebar photos remain blocked. Production DOCX, Legacy/V2, PDF and JSON paths were not switched or removed.

The header restriction follows an actual failed stress probe, not a hypothetical warning. Stable LibreOffice 25.8.7.3 rendered 14 dossier pages but omitted the second work entry and reference tail despite those texts being present in the native source package. Both a different first header and a single continuation header failed. The attempted first-page paragraph lead collapsed before the table; transferring it into top cell padding repeated the lead on subsequent pages. The candidate does not use either attempt. Development of those combinations stopped instead of introducing a repair chain. Hashes and missing fields are recorded in [evidence](sidebar-stress-evidence.json).
