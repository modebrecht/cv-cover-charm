# DOCX Next source and ownership boundary

The public compatibility snapshot still accepts `CoverPdfDocument`, `LetterPdfDocument` and `CvPdfDocument`. Their historical names do **not** imply measured PDF pages: Letter/CV contain saved app data/design, and Cover contains authored template blocks. No DOM rectangles, browser line breaks, browser page assignments or print pagination are consumed by Next.

`source-adapter.ts` explicitly copies these fields into neutral `DossierCoverSource`, `DossierLetterSource` and `DossierCvSource`. `source.ts`, model composition, layout policies and the single Word renderer import no PDF document types. This is an adapter boundary, not an app-wide data rewrite. Neutral sources remain structurally compatible with the shared semantic contact/chrome helper; that helper resolves saved contact and chrome values without browser measurement.

`coverFingerprint` and any future top-level PDF/measurement properties are excluded by the adapter. Boundary tests inject bogus `pages`, `pagination` and `measuredRows`, verify exclusion/immutable copies and verify an identical semantic model.

Browser text X/Y, fixed/minimum height, `follows`/`above`/bottom anchors and `maxLines` do not constrain native text pagination or cause browser auto-fit. Word-oriented flow keeps the selected font size and permits additional lines/pages. This explicit conversion policy needs visual/edit acceptance; it is not a promise of browser geometry parity. Text badge corners become native rectangular fill/borders. Translucent semantic images are blocking until native alpha has actual render/edit acceptance: LibreOfficeDev ignored `alphaModFix` in the attempted proof fixture. No opaque substitute is silently exported.

Older anonymous typography binds only through an explicit saved key/field ID to a canonical semantic ID. Unique visible values, labels and occurrence metadata never choose a target. Canonical IDs cannot be redirected; conflicting duplicate bindings throw before rendering. Missing/ambiguous bindings remain model issues that block the candidate.

## Cohesive ownership

- `build-model.ts`: dossier orchestration, letter/CV field mapping and semantic chrome mapping.
- `cover-composition.ts`: authored cover mapping, including known visibility and custom field flow.
- `continuation-margin.ts`: one native section margin/first-page lead policy after chrome reservation.
- `colors.ts`, `typography-bindings.ts`, `source-adapter.ts`: explicit color/source/identity normalization.
- `renderer.ts`: **one** renderer entrypoint, native block traversal and package/story ownership.
- `native-text.ts`: generic run/paragraph/list-mark/control primitives used by that renderer.
- Existing geometry/numbering/sections/elements/images/decoration modules retain their shared ownership.

Letter/CV/chrome mapping remains in the orchestrator because it shares style factories and field ownership. Further extraction is reasonable when diverse templates expose a coherent missing primitive; file length alone is not a reason to invent another architecture. Renderer primitives remain template-ID-free. Future templates configure shared primitives; they never generate OOXML.

Warm configures shared native cover rows, photo alignment, a growing compact sender cell, scoped header paint and explicit decorative page intersection. Authored shape geometry enters the neutral source; measured browser rectangles/page assignments do not. The shared native text reservation lives in `layouts.ts`; chrome composition uses a configured conservative line-metric factor for Word auto spacing, without changing authored run sizes or line-height properties. No template IDs enter the renderer. See [Warm flow policy](warm-feature-coverage.md).

Prism adds declarative palette-bound polygons via `template-motifs.ts` and grouped native cover cells. Cell widths constrain their mapped flow boxes before rendering; original source geometry remains metadata. A configured short letter tail uses native paragraph attachment and oversized tails stay splittable. Descriptor-owned default chrome paint distinguishes authored backgrounds from historical automatically resolved template surfaces; shared chrome contact/content and authored/default font/height are semantic presentation, not measured pagination. Brief/Warm output stays byte-identical. See [Prism flow policy](prism-feature-coverage.md).

Human configures the same native cover rows and contact bands. Generic per-part page motifs populate native first/default header stories independently of contact text; CV authored motif opacity scales decorative paint only. Existing ellipses represent soft corner/lower washes, with no lower CV echo. No renderer modification, PDF geometry dependency or template-ID branch was required. See [Human coverage](human-feature-coverage.md).

Orbit adds no browser/PDF measurement dependency. Palette-bound circle/outline policies configure the existing decoration primitives; native photo/no-photo clearance uses the existing hero lead. Descriptor-owned `cover.fieldAlignments` supplies native defaults only when authored `userStyleKeys` has no alignment override. This semantic override provenance is captured in neutral cover blocks and survives their immutable copy; no DOM coordinates or post-render text matching enters composition. See [Orbit flow policy](orbit-feature-coverage.md).

Cove, Glow and Horizon continue the same neutral source boundary. Optional independent rectangle corners and radial color-to-transparency fades belong to nonsemantic shape paint. Header-off fallback motifs are selected by captured first/continuation chrome mode and scaled by authored CV background opacity; dormant header surfaces do not erase that page paint. Invalid corners/fade ranges/opacity fail explicitly. New descriptors configure native cover rows, photos, alignment, gradients and chrome through the existing single renderer, which is unchanged in this batch. No PDF pagination geometry, XML repair or template-ID rendering branch was added.

## Opt-in semantic interior palettes

Descriptors may set `interiorPaletteSource: "dossier"` when cover ink differs from interior ink (for example, a light cover foreground on full-sheet paint). Composition then uses the existing pure app `resolveLetterPalette`, `resolveLetterPaperColor` and `resolveCvPalette` rules for native body/contact/footer text and interior paper. These functions consume authored colors and explicit paper/text overrides only. They do not inspect DOM rectangles, PDF fragments, page counts or pagination geometry. Canonical semantic field typography remains authoritative. Earlier descriptors retain their existing palette behavior; this is an adapter policy, not a wholesale data-model rewrite.

Cover `fieldPaletteMode: "uniform"` applies a declared field color to palette-bound inline runs before rendering. Literal authored inline colors and canonical field overrides keep precedence. Field identity comes from the explicit snapshot; no rendered text matching is involved.

Authored nonsemantic polygons may use bounded absolute `M/L/H/V/Z` shorthand. The element adapter expands `H/V/Z` into validated `M/L` points before composition, preserving saved position, dimensions, opacity, color and semantic element identity. Relative commands, curves mixed with shorthand, markup, unknown tokens and coordinates outside 0–100 fail explicitly. Declarative cubic motifs retain their separate bounded grammar. Templates never repair or generate XML.

Repeated full-sheet paint may declare explicit `paintLayer` values, independent of global DrawingML IDs. The native renderer uses these values for background stacking; the paper underlay is layer zero. Layered page policies declare all layers, and authored foreground geometry is composed above them. The same first/continuation stories work on covers and interiors. Actual two-page cover probes caught an importer ordering failure and now verify both initial render and save/reopen; no XML repair or template-ID renderer branch is involved. Unlayered existing descriptors retain their original package output.

Descriptors can declare `cover.heroStartFields` as an ordered list of semantic cover field IDs. Native composition uses the first present field when there is no photo, independently of name visibility; undeclared/empty start policies fail explicitly. Existing descriptors keep their name/photo policy and exact package bytes. Editorial configures kicker/profession/name starts, never measured browser coordinates.
