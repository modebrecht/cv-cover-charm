# Prism candidate coverage and native flow policy

**3/39 configured candidates (Brief, Warm, Prism); 0/39 Microsoft Word accepted.** Prism is isolated. Production DOCX still uses Legacy/V2. [Machine checkpoint](prism-stress-report.md) and [Word checklist](word-smoke-test.md) record separate acceptance requirements.

| Authored feature                          | Candidate representation / limit                                                                                                                                                                          |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Two-tone cover identity                   | Declarative normalized polygon paths in the first native header story. Nonsemantic paint only; no user text in artwork.                                                                                   |
| Cover label/date                          | Native two-cell row with a readable primary backdrop. Original text, canonical IDs, typography and saved colors remain authoritative.                                                                     |
| Name/profession/start date/photo          | Growing native two-cell composition. Several semantic fields share the left cell; native photo/crop/frame occupies the right cell. No fixed-height text container or browser transform.                   |

The cover's 111 mm diagonal hero is decorative design intent. A native spacer places the flowing hero composition below it. Photos, long fields and custom content can increase native row height and page count. Browser positions, CSS transforms, measured DOM/PDF boxes and browser pagination are not imported. Grouped field cells keep canonical IDs. Decorative paths already belong to the shared renderer; no new renderer or template-ID branch was needed.

Prism selects descriptor-owned chrome paint. The historical chrome adapter still resolves semantic contact/content, template-default font size and authored/default height; these are authored presentation values, not measured browser geometry. Its resolved default gradient is not misclassified as a user-selected surface or copied as Prism's paint. Brief/Warm retain their recorded policies and regenerate byte-identically. CV `bgOpacity` governs browser page motifs, not this independent chrome signature; this candidate places no CV body-background motif.

Native rectangular badges, cover flow, compressed chrome and polygon overlap are Word-oriented adaptations requiring human review. Light-palette fixtures explicitly author matching cover foregrounds. Other explicitly authored low-contrast colors remain exact; review/adjust those in Word rather than expecting automatic rewriting.

Explicitly blocked: ambiguous anonymous typography, free CV section positioning, continuation margins above the initial margin, translucent semantic images, unsupported font keys, enabled font embedding and Modern/sidebar. All model issues block candidate export. The other 36 templates fail registry lookup; no family/Legacy fallback occurs.

The fourteen representative scenarios cover normal content, long letter/CV, compact/none chrome, Timeline with an oversized entry, Magazin/half sections, photo/images, independent custom fields and rich content, signed continuation chrome, light colors, custom gradient surface, long values and native letter columns. Their 95 rendered pages are candidate evidence, not approved snapshots or Word acceptance.
